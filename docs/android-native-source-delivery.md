# Android native source delivery

The `rua-android-native-sources.tar.gz` archive is included in the release’s
`Rua_<version>_dependency-sources.tar.gz` asset alongside the ARM64 preview APK.
It contains the three upstream source archives, a pinned Termux packages snapshot
with build scripts and patches, native license texts, the native manifest, and
Rua's `stage-native-payload.py` transformation script. The manifest identifies
the downloaded binary package hashes separately from the source archive hashes.
The packaging job verifies all source hashes and checks that each recipe's
version and upstream source hash match the native manifest.

The recipe snapshot is `ead77f879d6e931b249f51e3a5f16a060759f933` from
<https://github.com/termux/termux-packages>. Its `packages/proot/`,
`packages/libtalloc/`, and `packages/libandroid-shmem/` directories contain the
matching version recipes and patches. The snapshot also contains the common
build infrastructure, toolchain configuration and download scripts. These
materials provide the source/build inputs; a bit-for-bit reproduction of the
upstream prebuilt packages has not been established.

PRoot and its loader are distributed under GPL-3.0-or-later, using the later
version option in their GPL-2.0-or-later source headers. talloc's library remains
LGPL-3.0-or-later; libandroid-shmem remains BSD-3-Clause. These independent native
components do not change the Apache-2.0 license on Rua's own code.

## Rebuild or replace a native component

1. Extract the Termux snapshot and upstream archives. Follow that snapshot's
   `CONTRIBUTING.md` and `scripts/run-docker.sh` instructions on a supported Linux
   build host. Use its `build-package.sh -a aarch64` command for
   `libandroid-shmem`, `libtalloc`, and `proot`, retaining your modifications.
   Toolchain requirements are recorded in the snapshot's build scripts.
2. Put the resulting `.deb` files under the Rua checkout's
   `target/native-runtime-inputs/`. Update the corresponding entries in
   `mobile/runtime/native-dependencies.json` to your package filenames, byte
   lengths and SHA-256 hashes. For source redistribution, update the source
   hashes and build recipe snapshot as well. Staging deliberately rejects a
   binary that does not match the manifest.
3. Run `scripts/package-mobile-apk.sh --debug --clean` with the documented Android
   build dependencies installed. Rua extracts the replacement ELF files,
   changes talloc's SONAME and PRoot's NEEDED entry to `libtalloc.so`, and builds
   a new APK. Runtime payload metadata is regenerated by the build.
4. Install the rebuilt development APK with
   `adb install -r target/mobile-apk/rua-debug-arm64-v8a.apk` on a test device.
   This preview uses `mobile/mobile-shell/app/testkey_untrusted.jks`; its public
   development credentials and signing configuration are in `app/build.gradle`.
   No private release signing key or vendor approval is required. A production
   APK signed with another key needs a separately installed application or an
   uninstall before changing its signing identity; preserve your data first.

The public test key permits rebuilding and installing a modified preview. It is
not a system-trusted release identity. Normal Android application signing rules
still apply. This procedure does not install Termux App or a Termux userspace.
The Rust runtime, Android host and full build wrapper are provided separately in
the same release’s GitHub-generated **Source code** downloads.
