# ADR 0057: Phone Use — Android 原生能力与私有执行边界

**Status:** Accepted

## Context

Rua 需要让手机上的 Agent 读取和操作 Android App，并使用手机摄像头。
APK 通过 Android 原生服务提供手机权限能力，并从 `nativeLibraryDir` 直接
启动独立的 Android ELF，以 `rua server start --profile mobile-apk` 运行
resident Runtime。resident 与原生权限服务通过私有认证通道协作；PRoot 内的
Linux 工具进程不获得该通道的启动凭据。原生权限执行与 Agent 授权具有明确
的所有权边界。

## 已确认方向

### D1 — APK 内置能力，不对外提供手机控制服务

Phone Use 集成在 Rua APK 内，不要求安装伴随应用。范围包括无障碍操作与
摄像头，两者权限分别控制；不包含隧道，也不开放外部 MCP 手机控制接口。
动作仅通过 Rua Agent 工具调用和授权链进入执行端。

优先使用 Android 官方 AccessibilityService 和 CameraX；第三方自动化项目
作为接口、实现和测试参考，不引入整套第三方 MCP 服务器或长期维护的裁剪版。
不得因采用第三方实现而弱化许可证、Stop、权限或设备隔离要求。

### D2 — 手机是执行设备，远端仅作为已认证的对话控制端

首期采用手机本机执行模式。使用 Phone Use 的 Chat/Turn 在手机 resident
Runtime 上执行，由该 Runtime 内的 Agent 调用本机能力。

用户可以从电脑等已认证的 Rua 控制端查看、发送消息和控制手机上执行的
对话；这不把 Phone Use 暴露为电脑上执行的 Agent 可直接选择目标手机调用
的远程工具。沿用现有 Conversation Authority、执行设备和审批/Stop 边界，
不在 Phone Use 内新增跨设备任务调度、授权转发或重试机制。

### D3 — 本机入口认证是启用 Phone Use 的前置条件

本次范围包含手机 resident Runtime 的入口认证加固，不能以现有 `--no-auth`
启动方式配合隐藏的原生接口，宣称 Phone Use 仅供 Rua Agent 使用。
认证边界未完成并通过验收时，不启用 Phone Use。

APK 自带界面自动建立受信连接，不要求用户每次输入密码；外部浏览器或电脑
控制端必须经过 Rua 认证。未认证调用不得通过创建对话、提交输入、直接
工具调用或批准请求间接驱动 Phone Use。界面连接认证不等于授予工具执行权限，
实际动作仍经过有效 Chat/Turn 授权与 Tool Guard。

`localhost`、同 UID 或调用参数中自报的 `agent_id` 都不是充分授权依据。
私有通信必须区分正常启动的 resident 与普通工具子进程，信任边界遵循 D10；
不承诺仅靠路径或令牌即可隔离同 UID 的任意恶意代码执行。

### D4 — 沿用 Tool Guard 与 Approval，无障碍和摄像头分别授权

Phone Use 不新增独立审批系统或手机控制授权会话。真实工具名称、动作及参数
在执行前进入现有 Tool Guard 和进程级 Approval，执行依据为有效
Chat/Turn 授权快照；沿用 ADR-0012 的规则优先级与审批复用范围。

Android 系统权限由用户在系统界面授予，Agent 不得代替用户批准。启用无障碍、
允许观察屏幕或普通点击，不授予摄像头使用权限；拍照使用独立工具权限和审批
规则。允许按现有规则复用授权，不强制每次普通点击都单独审批。

工具可见性不代替执行授权，系统权限撤销、Stop 及有效的拒绝规则不受已有
批准覆盖。沿用现有配置快照生效时点，不把配置编辑与即时 Stop 混为一谈。

底层不能仅凭坐标、控件文字或模型判断可靠识别所有付款、发送等业务后果。
不承诺自动识别一切敏感点击；Agent 遵守用户意图与操作授权，执行层负责
可验证的权限、目标、观察、生命周期与动作约束。

### D5 — 设备级控制权仅覆盖一次有界交互

同一手机的界面输入由设备级协调器串行执行，一次有界交互可以包含受限的小组
动作，但不能跨模型思考或多次工具调用长期占有屏幕。不同 Chat 不获得独立
虚拟屏幕；一次调用结束后，其他 Chat 可以取得控制权。

获取控制权后、动作派发前检查观察有效性及目标 App/窗口；排队或人工操作
导致目标失效时拒绝旧动作并要求重新观察，不自动恢复目标页面或重放输入。
一组动作内也必须检查目标变化与取消，不能以首次校验覆盖所有后续动作。
观察有效不能保证界面绝不在校验后变化，该竞态及无法确认的效果必须如实报告。

Chat 内的 Stop 取消该 Turn 尚未执行的后续动作和控制权等待，并有界结束本次
执行、释放控制权。
已提交给 Android 的手势或已产生的外部效果不承诺撤销；无法确认是否生效时
返回结果未知并要求重新观察。其他 Chat 的工作和用户应用不能因本次 Stop
被关闭。前台交互保持可中断，不强行抢回用户已经切换的界面。

### D6 — 仅执行期间显示的单次操作终止按钮

无障碍服务连接、应用启动或空闲时不显示悬浮窗。Agent 发起需要屏幕或相机
执行的 Phone Use 调用时显示一个轻量、明确标注“终止”的按钮；不显示总开关、
常驻状态条或“恢复”按钮。成功、失败、取消或服务退出后收起，不能遮挡后续
用户操作。只读连接状态/设备清单查询不创建悬浮控制层。

点击终止只取消当前这次 Phone Use 操作，原生端立即阻止该请求后续派发并
收起控件，将取消状态传递给 resident，不等待模型响应。相机调用还需释放
相机资源。已提交动作与结果未知的处理遵循 D5，不能宣称撤销了既有副作用。

不保留跨调用暂停状态，不要求用户恢复，也不终止整个 Agent、其他 Chat 或
普通对话。Agent 下次调用 Phone Use 可以正常重新执行；新动作仍需当前授权
和新观察，不自动续跑或重放已取消请求。清理未完成时保持短暂忙碌，避免与
新调用重叠；旧请求的晚到回调不能取消新请求或移除其控件。Chat 页 Stop
仍保持单 Turn 语义。

### D7 — 可见预览下的单次拍照

首期摄像头能力提供可见预览与 Agent 单次拍照，不包含后台静默拍摄、持续
视频流或录像。经现有 Tool Guard 授权后，请求进入 Rua 拍摄界面，显示真实
预览及正在使用的摄像头。Agent 可以触发单次拍照，不另行强制用户每张照片
按快门；用户始终可以终止当前拍摄。

无法按 Android 平台规则进入拍摄状态、权限不足或相机被占用时明确失败。
不得用无障碍代替用户批准系统权限或规避前后台限制。相机权限与无障碍权限
互不替代，不能以开启无障碍作为合法后台采集的依据。

拍摄完成、取消、权限撤销或超时后释放相机，不保留隐式持续采集。照片归属
发起调用的 Chat，沿用 ADR-0030 的媒体归属与传输机制，不默认写入系统相册。
成功返回照片与向模型展示图像按现有媒体契约区分，不能把图片路径或 base64
文本当成模型已经看见图像。

### D8 — 随应用正常启动，不建设自动恢复机制

首期不为 Phone Use 建设服务保活、自动拉起、崩溃恢复或操作续跑机制。服务
被系统杀掉或私有连接断开后，当前调用失败或报告结果未知，能力不可用即可；
通过应用正常启动重新初始化，不尝试自动修复。

不保存暂停或恢复状态。正常应用重启后按当前系统权限和 Rua 授权重新判断
可用性，旧请求不续跑。后续新调用不需要通过重启服务来恢复能力。

不恢复旧动作队列、旧观察句柄或未完成拍照，不自动重放结果未知的操作。
正常启动可用不等于自动执行；所有新操作仍必须经过当前授权和观察检查。
此决定不改变 Android 系统对无障碍服务的绑定行为，也不引入对系统服务调度
的接管。

### D9 — Phone Use 是受限工具组，不是通用命令入口

首期提供以下能力，具体工具名称和 DTO 在 PRD 中落实：

- 观察：当前 App、窗口、无障碍树和屏幕截图。
- 操作：点击、长按、输入、滑动、返回、回到桌面和启动 App。
- 摄像头：列出前后摄像头、可见预览下单次拍照。

观察与有界交互分离，执行前遵循 D5 校验，摄像头遵循 D4/D7 单独授权。
工具选择遵循 ADR-0058：普通 Agent/Chat 的 Default-Enabled 策略在 Android
执行设备上纳入新提供的 Phone Use 工具，保留整项能力和单个工具的显式禁用；
Restricted 模式只允许明确选中的工具。此选择不代替 D3/D4 的认证和系统授权，
也不允许从桌面执行的 Agent 远程直接调用手机能力。

不提供一个接收任意代码或命令的通用执行接口，不在本工具组中加入任意 Shell、
脚本执行、文件管理、录音、录像或隧道。此限制不改变 Rua 其他独立工具的范围。

### D10 — 私有原生通道，不扩展为同 UID 恶意代码沙箱

首期基于 Android 现有应用隔离模型。其他 Android App 不得直接访问 Phone Use
执行接口；APK 与 resident 的私有连接绑定实际启动的受信 Runtime，而非仅
检查 UID。普通 Shell、Skill、插件等子进程不得继承执行连接句柄或凭据，
不提供绕过 Chat/Turn 授权直接派发原生动作的正常调用入口。

一个 bridge generation 只接受一个经校验的 resident，不能由其他 PID 接管。
APK owner 停止该 resident 时关闭 bridge 并撤销其可用凭据；确认旧 resident
退出后，正常启动新 resident 创建新的 bridge、generation 和 token。等待认证
的调用方读取当前 generation，不能沿用已经关闭的旧连接或旧 token。

不承诺防御已攻陷 Rua 或已取得同 UID 任意恶意代码执行能力的攻击者。
同 UID 文件访问、代码篡改或进程攻击需要另行建立沙箱边界，不纳入本 ADR；
不得以私有 socket、路径、Token 或对端身份检查宣称已经提供该等级隔离。

私有 IPC 的具体传输选型在实施前依据 Android 真机能力核验，必须满足上述
身份、非继承、生命周期和取消约束；不因接入方便退回公开或仅回环绑定的
MCP/HTTP 控制服务。

### D11 — 一次观察授权一次有界交互的目标引用

观察返回由执行端签发或维护的 `observation_id`，关联当前 Chat、服务运行
实例、目标 App/窗口及屏幕坐标信息；观察本身不是工具授权凭据。点击、输入
等交互引用有效观察，不允许跨 Chat 复用或由调用者伪造有效状态。

一次观察最多用于一次有界交互，取得控制权后的有效性检查遵循 D5。App/窗口
切换、屏幕旋转、服务重启和该调用终止使旧观察失效；节点消失或目标无法确认
时拒绝执行。时钟刷新等与目标无关的动画不要求整份观察无条件失效。

一组动作造成页面切换后不得继续用旧节点或坐标操作新页面。启动 App、返回
和回到桌面可有意改变目标，但其后必须重新观察，不能自动点击新页面。
交互结束后返回新观察供后续调用使用；若观察失败，应分别报告已派发动作的
已知结果和观察失败，不得重放动作来补齐观察或将未知效果报告为成功。

## 验收底线

测试必须验证实际行为与界面效果，不能以工具返回成功代替操作成功。

1. 打开 App、中文输入、点击、长按、滑动和返回均验证实际界面结果。
2. 切换 App、屏幕旋转和跨 Chat 复用观察时拒绝旧动作；界面变化不得导致
   自动点击新页面或重放原动作。
3. 空闲不显示控件，执行时仅显示终止按钮；终止当前调用后立即收起且不续跑。
   清理结束后的下一次新调用无需恢复，仍需新观察；旧回调不影响新调用。
   Chat 内 Stop 只取消对应 Turn，不关闭用户应用。
4. 前后摄像头提供可见预览与单次拍照，照片返回正确 Chat；完成、取消、
   超时及权限撤销后释放相机并收起终止控件。设备没有对应摄像头时明确报告不可用。
5. 未认证入口、普通外部 App 和未持有私有连接的普通工具子进程不能绕过
   授权；无障碍与摄像头权限撤销、Tool Guard 拒绝分别有效。
6. 服务被杀后明确报告不可用或结果未知；应用正常重启重新初始化，不恢复
   旧动作或拍摄，不创建常驻悬浮控件。

自动化测试和模拟器用于日常验证；最终至少在一台真实 Android 手机上完成
上述验收，并记录设备型号、Android 版本、APK 构建与授权条件。不将所有机型
兼容作为首期目标，模拟器或 mock 测试不能代替真机验收。详细接口字段、
超时数值、测试步骤及平台差异矩阵在 PRD/Issues 中落实。

## Implementation status

Phone Use 尚未实现。现有无障碍占位服务不构成功能完成的证据。私有 IPC 具体
传输需在首个端到端切片中验证；若无法满足 D3/D10 的边界，必须先修订方案，
不得通过公开控制接口或弱化认证继续实现。
